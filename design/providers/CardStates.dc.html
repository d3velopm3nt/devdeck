Provider card — states
One card shape for every provider. Only the mark, the note and the status line change, so the row reads as a set rather than a list of special cases.
Default
OpenAI GPT models, direct. Not connected
Resting state. The mark carries the identity; the border stays neutral so a row of seven doesn't shimmer.
Selected
OpenRouter One key, most models. Good first choice. Connected
Selection borrows the provider's own hue rather than one global accent, so which card is active is legible at a glance without a second indicator.
Local — no key
Ollama Local models. Nothing leaves the machine. No key needed
"No key needed" is a state, not an absence. Saying it here stops the empty key field on the right reading as something unfinished.
Not available yet
Anthropic Claude models, direct from the source. Not available yet
Still selectable, and the panel explains why. Greying it out would leave people guessing whether it's broken or coming.
Why cards, not tabs
The old screen split on OpenAI-compatible vs Anthropic — the wire protocol, which is DevDeck's concern and not yours. Here the protocol is a line of small print under the name, and the thing you pick is the thing you were looking for.
One shape, one place
Every provider goes through the same form in the same position; only the fields it genuinely needs appear. Local providers lose the key field, custom endpoints gain a base URL and headers.
The marks
Drawn as abstract glyphs in each provider's rough hue — recognisable in a grid without borrowing anyone's trademark. Swap them for real logos if you have licence to.
