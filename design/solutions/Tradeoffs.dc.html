Atomic review Link each feature to the PRs that implement it, so the trail exists even though the merge does not. A context change and the code change it describes land in two repos, at two times. Nothing makes them one commit.
Branch-aware context The feature records branch per project; DevDeck warns when a repo has moved off the branch its feature names. Two people on different branches of one repo still share a single context file.
Free access control Keep the split at the workspace boundary: one config repo per client rather than one for everything. Within a workspace it is all-or-nothing. A contractor on one solution reads every solution in it.
Self-describing repos project.md carries the repo URL, so setup can clone the code from the config, or the config from the code. Clone a code repo on its own and it tells you nothing about the work in flight.
One list of projects The config repo is the source of truth; SQLite stays derived and is rebuilt from it — the rule .devdeck already follows. Safe, as long as nothing writes project identity to SQLite first.
