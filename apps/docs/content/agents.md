# Workers and managers

## Workers

A worker has a brief, skills, target and limits. Start with a bounded task and clear acceptance criteria. Inspect its proposed run before launching it.

Read the result or receipt after completion: changed files, output location, checks, open questions and any remaining work. Review the actual output as well as the summary.

## Managers

Managers organise goals and propose or delegate work. Their standing instructions describe the desired outcome. Keep responsibilities specific so two managers do not own the same decision accidentally.

## Permissions

Configure permissions for the target and task. Respond to approval requests in DevDeck. Do not assume every tool or command is available to every worker.

## Sessions and continuation

Continue the same task with its existing context where supported. For a new task, supply the relevant brief and target rather than relying on a previous conversation.

## Verification still needed

Runner setup, live-agent execution and recovery should be tested on the installed Windows build. A mock-provider demonstration does not prove a real worker can complete the task.
