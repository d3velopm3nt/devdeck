# Spaces, folders and repositories

## Workspace context

Use spaces and folders to organise personal, home and business work. Keep briefs, decisions and supporting documents near the work they describe. Explorer is the entry point to the existing folder structure.

## Linked project repositories

A project has a local working path. Commands and services use that path; code workers may use a separate Git worktree. Verify the target before starting work.

The intended model keeps shared context and reusable skills outside application source repositories. The current shared skills library is local personal storage; a fully Git-backed shared skills workspace should not be assumed available yet.

## Labels

Labels help identify a folder's purpose. In the current workflow implementation, selecting Workflow opens the workflow view. It replaces the folder's single existing label; multiple labels and automatic label-based routing are future work.

## Files as shared context

Write clear goals, input paths, expected outputs and completion criteria. Link to supporting files rather than assuming an agent can see every document. Keep machine-specific paths and credentials separate from reusable instructions.
