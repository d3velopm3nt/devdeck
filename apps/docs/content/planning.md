# Goals, features and work

## Goals

A goal describes the outcome and standing instructions. Use it to explain why the work matters and what success means.

## Features and work items

Break a feature into reviewable work items. Include the relevant repository, inputs and acceptance criteria. Track documentation and website work when the change affects them.

## Roadmaps

Use roadmap records to organise intended work. A roadmap idea is not a shipped capability. Keep release evidence separate from planning status.

## Example: a product feature

Record the feature brief, implementation task, guide update and website draft. A folder workflow can make docs depend on reviewed implementation. Its current steps still require manual starts.

The exact relationship between roadmap views and existing work records needs alignment with the installed build.
