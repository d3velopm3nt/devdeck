Where a file lands

DevDeck writes attachments to a folder you choose. That is the whole integration. Point it at a synced folder and they sync; point it anywhere else and they do not.

Why a folder, and not a Drive integration
no new scopeDrive's full scope is restricted exactly like Gmail's. Integrating properly would double the verification problem we just walked around.
not new exposurethese files already sit on Google's servers, inside Gmail. Copying them to Drive keeps them with the same vendor you already trusted.
your choiceDropbox, OneDrive, a plain local folder and a network share all work the same way, because the contract is a path.
Three snags, and what the design does about them
streaming Drive for Desktop streams by default, so a file can be an online-only placeholder. A read stalls, or fails with the network down. Say so in the setting, and recommend a mirrored folder.
collisions Everyone names it invoice.pdf. A folder per message id, which is also how you find the mail a file came from.
path length Windows still trips over 260 characters, and mail filenames are long and full of characters a path cannot hold. Sanitise and truncate the name, keep the original in the database.
